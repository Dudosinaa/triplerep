# Отчёт: самостоятельный префаб игрока

Дата: 17 ноября 2026 года. Unity: 6000.3.28f1.

## Результат

Создан `Assets/Level/Prefabs/Resources/Player.prefab`.
Он содержит игрока, его интерфейсы и эффект стресса. NPC, записки, осматриваемые предметы,
мишени и демонстрационная площадка в него не входят и при его создании не появляются.

В `Metro` и `Home` загрузчик теперь создаёт ресурс `Player`, а не `MergedGameplay`.
Если в сцене уже размещён игрок с `FirstPersonPlayer`, загрузчик использует его без создания второго.
Исходный `MergedGameplay.prefab` и тестовые сцены сохранены.

## Иерархия

Сохранённая структура префаба:

```text
Player
├─ Main Camera
│  └─ Pistol View Model
├─ Player UI
│  ├─ Document UI
│  │  ├─ Crosshair
│  │  ├─ Read Prompt
│  │  └─ Reading Panel
│  ├─ Item Inspection UI
│  ├─ Dialogue UI
│  ├─ Pistol HUD
│  ├─ Player EventSystem
│  └─ Player Hints
│     ├─ Consciousness Hint
│     └─ Smoking Hint
└─ Stress Effects [Volume]
```

На корне `Player` находятся `CharacterController`, источник шагов `AudioSource`,
`FirstPersonPlayer`, `DocumentReader`, `ItemInspector`, `DialogueController`, `PistolController`,
`PlayerStress`, `SmokingPromptUI`, `SmokingController` и `SceneSwitch`.
Скрипты оставлены вместе: существующие вызовы `GetComponent` продолжают находить соседние механики.
Начало координат префаба находится у ног персонажа.

Во время игры добавляются только служебные объекты и визуальные модели механик:

- Под `Pistol View Model` создаётся настроенная модель рук и пистолета из `HandsWeapon.asset`.
- Под `Main Camera` загружается `Original Smoking Model` из `StreamingAssets/Smoking/model.gltf`.
- Под игроком создаётся выключенная камера `Inspection Preview Camera`; при осмотре под ней временно появляется копия выбранного предмета.

Неиспользуемые `Dialogue Camera` и `Dialogue Player Body` в новый префаб не перенесены.
Диалог остаётся от первого лица.

## Что изменено

| Область | Изменение |
| --- | --- |
| `MergedGameBootstrap` | Загружает `Player`. Удалены создание тестового NPC, расстановка предметов и мишеней, добавление компонентов стресса/курения/сознания. |
| Сервисы локации | Подбор места появления, страховка от падения и переход по F остались у загрузчика. Коллайдеры окружения настраиваются в сцене вручную. `Location Help` и `Location Exit` принадлежат загрузчику сцены. |
| Уже размещённый игрок | Его камеры и слушатели сохраняются активными; при проверке свободного места игнорируется собственная капсула. Коллизии окружения не добавляются на модели игрока. |
| `DialogueController` | Собеседник определяется лучом под прицелом. Ссылка на конкретного `Demo NPC` удалена; подсказка показывает имя выбранного персонажа. |
| `PlayerStress` | Режим смешивания эффекта сохраняется в префабе и применяется в `Awake`. Создан `Assets/Settings/PlayerStressProfile.asset`. При нулевом стрессе вес эффекта равен нулю. |
| `SmokingController` | Использует собственную подсказку из префаба. Для сохранённой выключенной TMP-подсказки исправлена инициализация перед настройкой оформления. Сохранена совместимость с отдельным Canvas старой `StressDemo`. |
| `ItemInspector` | Камера и копия предмета принадлежат игроку. Перед осмотром положение камеры сбрасывается, чтобы движение игрока не смещало предпросмотр. |
| Проверки проекта | Проверяется новый префаб. Старые проверки оружия создают необходимые тестовые предметы самостоятельно, а не ожидают их появления от игрока. |

Связи чтения, осмотра, диалога, HUD, оружия, подсказок и эффектов находятся внутри нового префаба.
Настройки оружия, модель, анимации, материалы, звук стресса и файл курения остаются общими ресурсами проекта.
`PlayerMovement` из `StressDemo` в новый префаб не добавлен: используется один контроллер `FirstPersonPlayer`.

## Как использовать

1. Перенести `Assets/Level/Prefabs/Resources/Player.prefab` в сцену и расположить его ногами над полом с Collider.
2. Проверить, что в сцене один игрок, одна активная игровая камера и один активный `AudioListener`.
   В `Metro` и `Home` размещать игрока вручную необязательно: загрузчик создаст его сам.
3. Разместить интерактивные объекты отдельно от игрока:
   - записка: `ReadableDocument` и Collider;
   - предмет для осмотра: `InspectableItem` и Collider;
   - NPC: `NpcDialogue`, настроенные реплики и Collider;
   - вход в сознание: `FocusPoint` на объекте или дочерней точке NPC, с правильным индексом сцены.

`DialogueController` не требует назначения NPC в Inspector.
В префаб уже включён `EventSystem` с новым Input System. Если сцена содержит собственный `EventSystem`,
следует оставить один активный, например отключить `Player UI/Player EventSystem` у экземпляра игрока.
Индексы сцен сохранены: Metro — 0, Home — 1, ConsciousnessScene — 2.

В Inspector можно отдельно настраивать движение, расстояния взаимодействия, оружие,
скорость изменения стресса и внешний вид подсказки курения.
Стресс, курение и вход в сознание теперь видны среди компонентов сохранённого префаба.

выполнены в отдельной временной копии проекта; рабочие сцены не сохранялись тестовым процессом.

Play Mode проверил самостоятельный запуск без загрузчика, WASD, приседание, стрельбу,

## Ограничения и оставшиеся проверки

- В Metro во время проверки появлялось предупреждение `No clear spawn floor found`.
  Загрузчик использовал предусмотренную страховочную коллизию. Точку `spawnPosition`
  стоит отдельно уточнить относительно пола и окружающей геометрии; настройки сцены в этой работе не менялись.
- Внешний вид интерфейса, рук и освещения следует оценить в Game View на целевом разрешении.
  Автоматические проверки подтверждают инициализацию и размеры Canvas, но не заменяют художественную оценку.
- Отдельная сборка Windows не запускалась.

Для повторной проверки префаба доступна команда `Tools > Player > Validate standalone player prefab`.
`Tools > Player > Rebuild standalone player prefab` пересобирает его из исходного демонстрационного ресурса
и перезаписывает настройки самого ассета; для обычного использования эта команда не требуется.

Интеграционные проверки: запускать **отдельную копию проекта** обычным редактором Unity с параметрами
`-playerPrefabValidation -executeMethod PlayerPrefabPlayValidation.RunBatch`, без `-batchmode` и `-quit`.
Проверки используют виртуальные устройства ввода и временные объекты в памяти и завершают свой редактор автоматически.
Обычный редактор нужен для штатной блокировки курсора, от которой зависит доступность оружия.

Исходные игровые сцены, `MergedGameplay.prefab`, `HandsReload.prefab` и `HandsWeapon.asset` не изменены.
Существовавшие до начала работы файлы `Lab.unity` и `Lab.unity.meta` не затронуты.

## Последующее изменение: автоматические коллайдеры

По отдельному запросу удалены метод `AddEnvironmentColliders` и его вызов из `MergedGameBootstrap`.
При запуске Metro/Home загрузчик больше не добавляет `MeshCollider` моделям окружения.
Проверено отсутствие метода и вызовов `AddComponent<MeshCollider>` в `Assets/Code/Scripts`,
а также `git diff --check`. Play Mode после этого удаления повторно не запускался;
результаты интеграционных проверок выше относятся к предыдущей версии загрузчика.
