# The Karamazov train — локальное объединение

Открыть эту папку в Unity **6000.3.28f1**. Проект находится прямо здесь, без дополнительного уровня вложенности.
Используется только новый Input System; файл InputSystem_Actions взят из carx. Графические настройки, материалы,
освещение и окружение основаны на dudosinaa. Добавлен glTFast 6.21.0 для оригинальной анимации курения.

## Сцены и индексы

| Индекс | Сцена | Роль |
| --- | --- | --- |
| 0 | Assets/Level/Scenes/Locations/Metro.unity | Стартовая игровая локация |
| 1 | Assets/Level/Scenes/Locations/Home.unity | Игровой дом |
| 2 | Assets/Level/Scenes/Gameplay/ConsciousnessScene.unity | Заглушка сознания, Esc возвращает в сцену входа |
| 3 | Assets/Level/Scenes/Gameplay/CarxDemo.unity | Сохранённая демонстрация взаимодействий и оружия |
| 4 | Assets/Level/Scenes/Gameplay/StressDemo.unity | Сохранённый прототип стресса и сознания |

SceneSwitch и FocusPoint используют числовые индексы. При изменении порядка сцен нужно обновить их настройки.
Characters, предпросмотр материалов и _Recovery сохранены, но не включены в список сборки.

## Управление

- WASD — движение; мышь — обзор; Ctrl — присесть; Esc — освободить курсор или закрыть открытое взаимодействие.
- E — чтение, осмотр или диалог. Для осматриваемого предмета ЛКМ вращает модель, колесо меняет масштаб.
- В диалоге 1–3 выбирают ответ, E/пробел продолжают ответ, Esc завершает разговор.
- ЛКМ — выстрел; ПКМ — прицел; R — перезарядка; Q — убрать/достать пистолет.
- Пробел повышает стресс, минус снижает; при стрессе от 40 клавиша Y запускает курение и последующее восстановление.
- T при взгляде на NPC в пределах взаимодействия — вход в сознание; Esc — возврат в исходную сцену.
- F рядом с голубым маркером у места появления — переход между метро и домом.

## Что объединено

- dudosinaa: Metro, Home, модели персонажей, анимация вставания, материалы, освещение и инструменты дома.
- carx: игрок, шаги, чтение документов, осмотр, диалоги, логика оружия, HUD и мишени.
- stress-mechanik: механика стресса, курение, подсказки, NPC и переход в сознание.
- Vadsu: общие скрипты и ресурсы уже содержатся в stress-mechanik; повторные копии не добавлены.

Рабочий игрок: `Assets/Level/Prefabs/Resources/Player.prefab`. Внутри находятся управление,
камера, оружие, чтение, осмотр, диалоги, стресс, курение, интерфейсы и эффект стресса.
Префаб можно перенести в сцену целиком; начало координат — у ног персонажа.

`MergedGameBootstrap` в Metro/Home обслуживает только подсказки и камеру уже размещённого игрока.
Игрока нужно вручную перенести из `Assets/Level/Prefabs/Resources/Player.prefab` в каждую игровую сцену:
без размещённого экземпляра сцена остаётся без игрока. Его положение и поворот задаются в сцене.
Переход выполняется входом в невидимую `Location Transition Zone`: затемнение, асинхронная загрузка,
появление целевой сцены с её собственным игроком. Настройка и результаты проверки:
[LOCATION_TRANSITION_REPORT.md](LOCATION_TRANSITION_REPORT.md).
Коллайдеры окружения настраиваются вручную.
NPC, документы, предметы и мишени автоматически больше не появляются. Их следует размещать в сцене
отдельно: `NpcDialogue` + Collider для разговора, `ReadableDocument` + Collider для записки,
`InspectableItem` + Collider для осмотра, `FocusPoint` у NPC для входа в сознание.
Диалог выбирает NPC под прицелом без ссылки на конкретного персонажа.

`MergedGameplay.prefab`, `CarxDemo` и `StressDemo` сохранены как демонстрационные ресурсы.
Подробная структура нового игрока, порядок использования и результаты проверок: [PLAYER_PREFAB_REPORT.md](PLAYER_PREFAB_REPORT.md).

## Проверка

Сначала дождаться окончания импорта и проверить Console. Затем запустить **Tools > Merge > Validate project**.
Для сборки: **Tools > Merge > Build Windows x64** (нужен модуль Windows Build Support).
Результат сборки: Builds/Windows/KaramazovTrain.exe. Отчёт редакторской проверки: Logs/Merge/unity-validation.json.

Актуальные результаты компиляции и проверок нового игрока приведены в [PLAYER_PREFAB_REPORT.md](PLAYER_PREFAB_REPORT.md).
Проверка отдельной сборки Windows выполняется дополнительно.

Вручную оценить точки появления и коллизии в обеих локациях, вид рук и интерфейсов;
проверять демонстрационные документы, предметы и NPC в CarxDemo либо размещать свои объекты в сценах.
Player следует размещать над полом с Collider; автоматического поиска пола, страховочной
площадки и возврата упавшего игрока к точке появления больше нет.

Исходная вложенная папка triplerep-main с .gitignore оставлена без изменений. Инструкции восстановления,
контрольные суммы и отчёт объединения находятся в _merge-backups рядом с проектом.

Неиспользуемый исходник Blender перенесён в SourceAssets/Authoring с метаданными; для игры используется glTF/FBX. Это исключает обязательный импорт через внешний Blender.
